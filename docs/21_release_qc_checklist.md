# 发布质检清单（质检角色操作手册）

> 用途：每次交付前，切换为「质检角色」逐项实证检查
> 依据：`19_update_delivery_spec.md` 第五章
> 原则：**只认命令输出，不认主观记忆**

---

## 使用方式

AI 在每次回复末尾，必须：

1. 按本清单**实际执行命令**
2. 把输出贴进「质检结果」表格
3. 任一 🔴 项不通过 → **禁止发布**，先修复

---

## 第 1 关：文件存在性 🔴

> 检查：声明的每个新增/修改文件，磁盘上是否真的存在

```bash
ls -la <文件路径>
```

| # | 检查项 | 命令 | 结果 |
|---|---|---|---|
| 1.1 | 声明的新增文件存在 | `ls -la <路径>` | ☐ |
| 1.2 | 声明的修改文件存在 | `ls -la <路径>` | ☐ |
| 1.3 | 文件非空（字节数 > 0） | `ls -la` 看 size | ☐ |

**不通过**：文件不存在 → 立即创建，不得发布。

> ⚠️ **FIX-006 教训**：
> 在回复里描述文件功能 ≠ 创建了文件。
> 必须先 `ls` 确认。

---

## 第 2 关：改动落盘 🔴

> 检查：声称改了的内容，文件里是否真有

```bash
grep -c "<关键字>" <文件路径>
```

| # | 检查项 | 命令 | 结果 |
|---|---|---|---|
| 2.1 | 新增的字段/函数能 grep 到 | `grep -c "review_key" xxx.sql` | ☐ |
| 2.2 | 删除的旧内容确实没了 | `grep -c "旧内容" xxx` → 应为 0 | ☐ |
| 2.3 | 修改的行号与声明一致 | 读取目标行确认 | ☐ |

**不通过**：grep 不到 → 说明没写入，立即补写。

> ⚠️ **FIX-005 教训**：
> 沙箱里验证方案可行 ≠ 改动写回了项目文件。

---

## 第 3 关：完整性 🔴

> 检查：文件是否完整、可解析、语法正确

### 3.1 文件完整性

| # | 检查项 | 命令 | 结果 |
|---|---|---|---|
| 3.1.1 | 无「省略」占位符 | `grep -c "省略\|...（" <文件>` → 应为 0 | ☐ |
| 3.1.2 | 文件行数合理 | `wc -l <文件>` | ☐ |

### 3.2 语法校验

| 文件类型 | 命令 | 结果 |
|---|---|---|
| YAML | `python -c "import yaml;yaml.safe_load(open(f,encoding='utf-8'))"` | ☐ |
| Python | `python -c "import ast;ast.parse(open(f,encoding='utf-8').read())"` | ☐ |
| PowerShell | 检查 BOM + 大括号配平 | ☐ |
| SQL | 检查 Jinja 括号、分号结尾 | ☐ |

### 3.3 编码检查（Windows 项目必查）

| # | 检查项 | 命令 | 结果 |
|---|---|---|---|
| 3.3.1 | PowerShell 脚本有 BOM | `xxd -l 3 <file>` → `efbbbf` | ☐ |
| 3.3.2 | 中文内容未乱码 | `grep "<中文关键词>"` 能匹配 | ☐ |

> 无 BOM 的 UTF-8 在 PowerShell 5.1 会按 ANSI(GBK) 读 → 中文乱码。

**不通过**：语法错误 → 修正后重检。

## 第 4 关：一致性 🟡

> 检查：文档描述与实际是否对得上

| # | 检查项 | 命令 | 结果 |
|---|---|---|---|
| 4.1 | 文档中的数字 = 代码实际 | 对比 `dbt test` 输出 | ☐ |
| 4.2 | 文档描述的参数 = 脚本实际参数 | `grep "param(" -A5` | ☐ |
| 4.3 | 新增文件已打包进 zip | `unzip -l <zip> \| grep <文件名>` | ☐ |
| 4.4 | 交付包内无顶层目录嵌套 | `unzip -l <zip> \| head` | ☐ |
| 4.5 | 文档引用的文件真实存在 | 逐个 `ls` | ☐ |

**不通过**：修正后放行（不阻断，但必须改）。

## 为什么质检必须是实证命令

| 方式 | 可靠性 |
|---|---|
| "我记得我写了" | ❌ 已证明不可靠（连犯 2 次） |
| "我确认过了" | ❌ 主观，无证据 |
| **贴出 `ls`/`grep` 输出** | ✅ **命令输出无法伪造** |

> **核心洞察**：
> 把质检从"我检查一下"变成"执行这些命令并贴输出"。
> **可验证性**是唯一可靠的保障。
