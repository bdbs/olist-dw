## 六、质检方法论说明

### 6.1 检查维度

```
静态检查（不运行代码）
  ├── YAML 解析性
  ├── Jinja 语法
  ├── Python 语法
  └── 依赖完整性（悬空引用）

内容检查（交叉核对）
  ├── 数字一致性（文档间是否矛盾）
  ├── 过时内容残留
  └── 命令写法正确性

规范检查（对照规范文档）
  ├── 命名前缀
  ├── 元数据完整性
  └── 质检规则覆盖度

运行时检查（实际执行）
  ├── dbt debug / run / test
  └── 数据装载验证
```

### 6.2 判定标准

| 级别 | 判定 | 处理 |
|---|---|---|
| 🔴 严重 | 导致代码无法运行或结论错误 | 必须修复后方可交付 |
| 🟡 一般 | 影响完整性但不阻塞 | 建议修复 |
| ⚪ 优化 | 体验或扩展性改进 | 可选 |

### 6.3 复检建议

每次重大变更后（切换数据源、新增模型、修改口径），
应重新执行本检查清单，重点复检：
- 文档中的数字是否与新数据一致
- 新增模型是否符合命名规范
- 新增字段是否有元数据描述
